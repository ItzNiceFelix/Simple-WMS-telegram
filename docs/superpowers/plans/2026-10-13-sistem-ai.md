### 1.3 Nol enkripsi di repo

Grep `encrypt|decrypt|aes|CryptoKey|GCM` → **nol**. Yang ada hanya hashing/HMAC:
- `worker/auth.ts:44-55` — PBKDF2-SHA256 100k iter (password)

### 1.4 Tidak ada binding untuk gambar

`wrangler.jsonc` — tidak ada R2, KV, Vectorize, AI. Untuk image gen, perlu R2 (simpan hasil) atau kirim langsung ke Telegram (tak perlu R2).

### 4.1 Alur data

### 4.2 Tabel baru (migrasi 0020)

```sql
-- Kredensial provider (ciphertext AES-GCM; plaintext TIDAK pernah masuk DB)
CREATE TABLE ai_kredensial (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  provider   TEXT NOT NULL,                -- groq | gemini | kenari | openai | openrouter
  label      TEXT NOT NULL DEFAULT '',     -- nama bebas, mis. "Groq utama"
  ciphertext TEXT NOT NULL,                -- base64
  iv         TEXT NOT NULL,                -- base64, 12 byte
  tag        TEXT NOT NULL,                -- base64, 16 byte
  aktif      INTEGER NOT NULL DEFAULT 1,
  dibuat_at  INTEGER NOT NULL DEFAULT (unixepoch()),
  dibuat_oleh TEXT,
  diuji_at   INTEGER,                      -- terakhir tes koneksi sukses
  diuji_hasil TEXT                         -- JSON ringkas hasil terakhir
);

-- Katalog model (user bisa tambah sendiri; sumber awal dari GET /v1/models provider)
CREATE TABLE ai_model (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  provider   TEXT NOT NULL,
  model_id   TEXT NOT NULL,               -- mis. openai/gpt-oss-120b
  label      TEXT NOT NULL DEFAULT '',
  jenis      TEXT NOT NULL DEFAULT 'teks', -- teks | gambar
  aktif      INTEGER NOT NULL DEFAULT 1,
  ditambah_at INTEGER NOT NULL DEFAULT (unixepoch()),
  UNIQUE (provider, model_id)
);

-- Pengaturan AI diperluas (tetap di tabel settings key 'ai', JSON)
--   textProvider, imageProvider, fallbackChain[], modelTeks, modelGambar, timeoutMs
```

### 4.3 Kunci enkripsi

Worker secret `AI_KEY_ENCRYPTION_KEY` (32 byte, base64). Dibuat sekali:
```
node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"
npx wrangler secret put AI_KEY_ENCRYPTION_KEY
```
WebCrypto AES-GCM — sudah ada di Workers, **nol dependensi baru**. IV acak 12 byte per enkripsi. Kalau kunci hilang, key di DB tak bisa didekripsi (harus isi ulang) — ini tradeoff yang benar dibanding menyimpan kunci di sebelah ciphertext.

## 5. Fase kerja

Setiap fase selesai = bisa dipakai, bukan scaffold.

### Fase A — Kredensial & katalog model (fondasi)
1. Migrasi `0020_ai_kredensial.sql` (3 tabel di atas).
2. `lib/ai/kripto.ts` — `enkripsi(teks)`, `dekripsi(ciphertext, iv, tag)` pakai WebCrypto AES-GCM.
3. `lib/d1/aiKredensial.ts` — CRUD: `simpanKredensial`, `ambilKredensial`, `daftarKredensial` (mask), `hapusKredensial`, `catatUji`.
4. `lib/d1/aiModel.ts` — CRUD katalog model.
5. Route: `POST/GET/DELETE /api/pengaturan/ai/kredensial`, `/api/pengaturan/ai/model`.
6. Perluas `ambilPengaturanAI`/`simpanProviderAI` (fallback chain, model teks/gambar).
7. UI: kartu Kredensial + kartu Model di `/pengaturan`.
8. Test: enkripsi round-trip, CRUD, mask tidak bocor plaintext.

### Fase B — Adapter provider + tes koneksi
1. Port `lib/ai/adapters/openaiCompat.js` → `lib/ai/adapterOpenai.ts` (retry 5xx, AbortController, timeout).
2. `lib/ai/adapterGemini.ts` — pakai SDK `@google/generative-ai` yang sudah ada, atau REST langsung (lebih ringan untuk Workers).
3. `lib/ai/provider.ts` — `panggilTeks()`, `panggilGambar()`, `panggilVision()`, fallback chain, dekripsi kredensial.
4. `GET /api/pengaturan/ai/model?provider=X` → ambil daftar model dari provider (`GET /v1/models`), isi katalog.
5. `POST /api/pengaturan/ai/uji` → tes koneksi + validitas nama model (kirim prompt minimal, laporkan latensi + pesan error asli provider).
6. UI: tombol "Muat dari provider", "Tambah manual", "Tes koneksi" dengan hasil jelas.

### Fase C — Bot menjawab teks
1. Port `lib/gemini/tools.js` (11 tool) → `lib/ai/tools.ts`, ganti sumber data Firestore → D1 (`lib/d1/*`).
2. Port `lib/gemini/promptSystem.js` → `lib/ai/prompt.ts`.
3. Port `lib/gemini/rateLimit.js` → `lib/ai/rateLimit.ts`.
4. `lib/ai/chat.ts` — orchestrator: loop tool-call, pendingAction, konfirmasi ya/tidak.
5. Sambung `worker/bot.ts`: teks biasa → AI (ganti pesan "menyusul"). Simpan riwayat di `bot_sessions.history_json` (kolom sudah ada, belum dipakai).
6. UI: pengaturan prompt sistem + maks loop tool-call.

### Fase D — Vision & gambar
1. Port `lib/gemini/ekstrakPickingList.js` → `lib/ai/vision.ts` (screenshot → picking list).
2. `lib/ai/gambar.ts` — image gen (Nano Banana 2.1 / `gemini-3.1-flash-image`).
3. Keputusan penyimpanan gambar: kirim langsung ke Telegram (tanpa R2) atau R2 (kalau perlu riwayat). **Perlu keputusan user.**
4. Sambung foto masuk di `worker/bot.ts`.

## 6. Risiko & hal yang harus diputuskan

| Risiko | Dampak | Mitigasi |
|---|---|---|
| Tiga daftar provider harus sinkron | Tambah provider = ubah 3 file + test | Jadikan DB sumber tunggal (Fase A) lalu sederhanakan paritas |
| Stack lama jadi kode mati menumpuk | Bingung mana yang benar | Hapus `lib/gemini/groqClient.js` (sudah mati), tandai `lib/ai/*` sebagai legacy |
| Kunci enkripsi hilang | Key DB tak terbaca | Dokumentasi jelas + perintah buat kunci di dokumen ini |
| Model `-latest` hot-swap | Perilaku berubah tanpa deploy | Default ke versi stabil (`gemini-3.8-flash`), `-latest` opsional |
| AI memanggil tool tulis (stok) | Salah ubah stok | Pertahankan desain lama: konfirmasi ya/tidak sebelum efek nyata |
| Biaya API tak terpantau | Tagihan membengkak | Catat pemakaian per hari (tabel `ai_pemakaian`), tampilkan di UI |
