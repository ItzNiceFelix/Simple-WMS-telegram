### 1.5 Dukungan anotasi gambar — TERVERIFIKASI

Ini yang menentukan fitur komentar-di-gambar yang kamu minta.

**a. Inpainting = semantic masking, BUKAN koordinat.** Dokumentasi resmi (`image-generation` → "2. Inpainting (semantic masking)") memakai template bahasa:
```
Using the provided image, change only the [specific element] to [new element].
Keep everything else in the image exactly the same, preserving the original
style, lighting, and composition.
```
→ Model mengerti area dari **uraian bahasa**, bukan dari koordinat piksel.

**b. Model BISA mengembalikan koordinat** (`image-understanding` → "Object detection"):
```
box_2d: [ymin, xmin, ymax, xmax] normalized to 0-1000
mask: polygon [x,y] normalized to 0-1000   ← segmentation mask
```

**Konsekuensi desain (penting):** dua arah ini bisa dipadukan.
User menggambar lingkaran di koordinat (x,y) → sistem minta model mengidentifikasi objek di area itu → dapat `box_2d` + label → label itu jadi bagian prompt.

Contoh alur:
```
User lingkari area → klien kirim gambar + koordinat lingkaran
  → model: "Apa objek di area ini?" → { box_2d: [...], label: "bayangan produk" }
  → prompt final: "Change only the shadow under the product to be softer.
                   Keep everything else exactly the same."
```
Ini membuat revisi presisi **tanpa perlu mode inpainting khusus** — cukup AI menerjemahkan area yang dilingkari jadi deskripsi objek.

### 3.2 Migrasi `0020_ai.sql`

```sql
-- Kredensial provider. Plaintext TIDAK PERNAH masuk DB.
CREATE TABLE ai_kredensial (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  provider     TEXT NOT NULL,          -- groq|gemini|kenari|openai|openrouter
  label        TEXT NOT NULL DEFAULT '',
  ciphertext   TEXT NOT NULL,          -- base64
  iv           TEXT NOT NULL,          -- base64, 12 byte
  tag          TEXT NOT NULL,          -- base64, 16 byte
  aktif        INTEGER NOT NULL DEFAULT 1,
  dibuat_at    INTEGER NOT NULL DEFAULT (unixepoch()),
  dibuat_oleh  TEXT,
  uji_at       INTEGER,
  uji_hasil    TEXT                     -- JSON: {ok, latencyMs, model, error}
);

-- Katalog model. Sumber awal: GET /v1/models provider.
CREATE TABLE ai_model (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  provider  TEXT NOT NULL,
  model_id  TEXT NOT NULL,             -- mis. openai/gpt-oss-120b
  label     TEXT NOT NULL DEFAULT '',
  jenis     TEXT NOT NULL DEFAULT 'teks',  -- teks|gambar|vision
  aktif     INTEGER NOT NULL DEFAULT 1,
  ditambah_at INTEGER NOT NULL DEFAULT (unixepoch()),
  UNIQUE (provider, model_id)
);

-- Preset prompt gambar (untuk foto produk listing)
CREATE TABLE ai_preset_prompt (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  nama      TEXT NOT NULL,
  kategori  TEXT NOT NULL DEFAULT 'produk',  -- produk|latar|gaya|lain
  prompt    TEXT NOT NULL,
  urutan    INTEGER NOT NULL DEFAULT 0,
  aktif     INTEGER NOT NULL DEFAULT 1,
  dibuat_at INTEGER NOT NULL DEFAULT (unixepoch())
);

-- Hemat token: catat pemakaian agar biaya terpantau
CREATE TABLE ai_pemakaian (
  tanggal   TEXT NOT NULL,             -- YYYY-MM-DD (WIB)
  provider  TEXT NOT NULL,
  model     TEXT NOT NULL,
  jenis     TEXT NOT NULL,             -- teks|gambar|vision
  panggilan INTEGER NOT NULL DEFAULT 0,
  token_masuk  INTEGER NOT NULL DEFAULT 0,
  token_keluar INTEGER NOT NULL DEFAULT 0,
  PRIMARY KEY (tanggal, provider, model, jenis)
);
```

`settings` key `'ai'` diperluas (tetap JSON):
```jsonc
{
  "textProvider": "groq",
  "imageProvider": "gemini",
  "chainTeks": ["groq", "gemini"],       // fallback per provider
  "chainGambar": ["gemini"],             // fallback gambar
  "modelTeks": { "groq": "openai/gpt-oss-120b", "gemini": "gemini-3.8-flash" },
  "modelGambar": { "gemini": "gemini-nano-banana-2.1" },
  "modelVision": { "gemini": "gemini-3.8-flash" },
  "maksRiwayat": 10,                     // hemat token: N pesan terakhir
  "maksLoopTool": 5,
  "rateLimitPerMenit": 20,
  "promptSistem": "..."                  // bisa diedit dari UI
}
```

**Model fallback per provider** = `modelTeks`/`modelGambar` berupa objek `{provider: model}`. Bila model utama gagal (404 model tidak ada, 429, 5xx), sistem coba model cadangan di provider yang sama, baru pindah ke provider berikutnya di `chainTeks`.

### 3.3 Hemat token — tiga lapis

| Lapis | Cara | Hemat (perkiraan) |
|---|---|---|
| 1. Riwayat | Kirim hanya N pesan terakhir (`maksRiwayat`, default 10) + ringkasan 1 paragraf untuk yang lebih lama | 40–70% pada chat panjang |
| 2. Tool selektif | Kirim hanya tool yang relevan dengan pesan; sisanya tidak | 50–70% dari bagian tool |
| 3. Cache prompt | Prompt sistem + deklarasi tool statis → `cache_control` (Gemini implicit caching / Groq) | 30–90% pada bagian statis |

**Deteksi tool relevan** (lapis 2) tanpa AI tambahan: pemetaan kata kunci → tool.
```
stok|ada berapa|sisa|qty        → cekStok, cariProduk
menipis|hampir habis|reorder    → cekProdukStokMenipis
tambah|kurang|koreksi|datang    → tambahStok, kurangiStok (+Batch)
cari|kode|sku|nama              → cariProduk
online|kolam                    → listProdukOnlineBesertaStok
(ragu / tak cocok)              → kirim SEMUA 8 tool (jaring aman)
```
Ini deterministik, gratis, dan mudah ditelusuri saat salah.

## 4. Halaman baru `/ai-gambar`

Gaya GPT: preview sebelum kirim, komentar di gambar.

```
┌─ Chat Gambar Produk ──────────────────────────────┐
│ [Preset ▾] Latar putih bersih │ Latar kayu │      │
│            Studio lighting    │ Tanpa bayangan    │
├───────────────────────────────────────────────────┤
│  ┌─ Preview ────────────┐  ┌─ Referensi (maks 5) ┐│
│  │                      │  │ [+ Tambah gambar]  ││
│  │   [gambar hasil]     │  │ [img][img][img]    ││
│  │   (klik utk komentar)│  │  ↑ referensi edit  ││
│  └──────────────────────┘  └────────────────────┘│
│                                                   │
│  Komentar: ● titik  ○ area (lingkari)             │
│  ┌───────────────────────────────────────────────┐│
│  │ prompt muncul di sini saat preset diklik      ││
│  └───────────────────────────────────────────────┘│
│  [Kirim]  [Kirim ke Telegram]  [Simpan lokal]     │
└───────────────────────────────────────────────────┘
```

**Alur komentar revisi (terverifikasi bisa):**
1. User klik titik / gambar lingkaran di area gambar hasil
2. Komentar ditulis ("bayangan terlalu keras", "warna agak gelap")
3. Klien kirim: gambar + koordinat + komentar
4. Model identifikasi objek di area itu → `box_2d` + label
5. Prompt final = template inpainting + label area + komentar user
6. Hasil baru tampil di preview — bisa dikomentari lagi (iterasi)

**Preset prompt:** klik preset → teks **muncul di kolom chat, belum terkirim** (sesuai permintaanmu). Preset awal untuk foto produk:
- Latar putih bersih (syarat Shopee/Tokopedia)
- Latar kayu / marmer
- Studio lighting lembut
- Tanpa bayangan keras
- Foto sudut 45° (produk terlihat 3D)
- Perbaiki pencahayaan saja (pertahankan produk apa adanya)

**Gambar referensi (maks 5):** untuk mode edit — kirim foto produk asli sebagai acuan sehingga bentuk/warna produk tetap setia. Ini penting: tanpa referensi, model cenderung "mengarang" produk.

**Hasil tidak masuk database** — sesuai keputusanmu. Preview dipegang di memori klien; "Simpan lokal" = unduh; "Kirim ke Telegram" = kirim ke chat user yang minta.


```ts
const teks = (text ?? caption ?? "").trim();   // :373
```

- **3 gudang aktif**, tool lama (`lib/gemini/tools.js`) hanya menyebut **"gudang online"** di 5 tempat (`:59`, `:78`, `:88`, `:105`, `:179`, `:218`, `:292`).
- **252 SKU (52% dari 482) ada di 2 gudang sekaligus** dengan qty berbeda.
- Contoh nyata: SKU `001163` → D12 = **0**, D19 = **7**.

**Kenapa ini penting:** pertanyaan "stok 001163 berapa?" punya **jawaban berbeda** tergantung gudang. Tool lama akan:
1. Menjawab stok `ONLINE` saja → jawabannya **0** (salah, karena gudang ONLINE kosong)
2. Atau menjumlahkan semua → **7** tanpa sebut di gudang mana (menyesatkan untuk operasi gudang)

Untuk koreksi stok (`tambahStok`/`kurangiStok`), tool lama **tidak meneruskan `gudangId`** — padahal `lib/d1/stok.ts:74` `ubahRelatif(db, sku, gudangId, delta, ...)` **sudah** menerima parameter itu. Jadi fondasinya siap; yang kurang hanya tool-nya.

**KEPUTUSAN (dikoreksi user): TIDAK ADA default gudang untuk AI.** Default gudang akan membuat AI menebak dan bingung — dua admin di gudang berbeda akan dapat jawaban berbeda untuk pertanyaan yang sama, dan AI tak bisa membedakan "karena default" dari "karena user memang minta gudang itu".

`user_warehouses` **tidak dipakai** sebagai default AI. Ia tetap dipakai untuk RBAC di dashboard (batas akses halaman), bukan untuk menebak maksud pesan.

**Aturan final:**
- **Baca tanpa menyebut gudang** → tampilkan **SEMUA gudang** dengan rincian per gudang. Contoh jawaban bot:
  ```
  001163 — Tatakan Kompor Rinnai
    Gudang D12 : 0
    Gudang D19 : 7
  Total: 7
  ```
  Bukan satu angka. AI **tidak menebak**.
- **Baca sambil menyebut gudang** ("stok di D19") → tampilkan gudang itu saja, sebut namanya.
- **Tulis SELALU butuh gudang eksplisit.** Tidak ada default, tidak ada tebakan. Bila pesan tidak menyebut gudang → bot **bertanya**:
  ```
  Tambah 5 pcs ke gudang mana? D12 / D19
  ```


**Keputusan desain (final):**
1. Semua tool baca menerima `gudang` **opsional**. Kosong → **semua gudang** dengan rincian. Tidak ada default, tidak ada tebakan.
2. Semua tool tulis (`tambahStok`/`kurangiStok`) **wajib** gudang eksplisit dari pesan. Tidak menyebut → bot **bertanya**, tidak menebak.
3. Tambah tool `daftarGudang` supaya bot tahu nama-nama gudang yang valid.
4. Tool `mutasiAntarGudang` (sudah ada di `lib/d1/stok.ts:90`) ditambahkan — ini kebutuhan nyata multi-gudang yang tool lama tidak punya.

**Perhatian saat implementasi:** `app/api/baca/route.ts:65` sekarang **diam-diam jatuh ke `ONLINE`** bila `gudang_id` kosong:
```ts
const nilai = gudangFilter ? (qtyMap[gudangFilter] ?? 0) : (qtyMap.ONLINE ?? 0);
```
Ini tepat pola yang bikin salah — dan karena gudang `ONLINE` **kosong 0 baris** di produksi, hampir semua SKU akan tampil **stok 0**. Tool AI **tidak boleh** memakai jalur ini apa adanya; ia harus membaca `qty_per_gudang` (`route.ts:71`, sudah tersedia lengkap) dan menyusun rincian per gudang sendiri.

**Hasil: 8 tool → 9 tool** (tambah `daftarGudang` + `mutasiAntarGudang`, tetap buang 3 tool yang sudah punya UI).

### 10.2 Login pakai username (bukan cuma telegramId)

Masalah nyata: telegramId 10 digit susah diingat.

**Kondisi sekarang (terverifikasi):**
- Kolom `users.username` **sudah ada** (`migrations/0011_users_guest.sql:8`) dan **sudah di-SELECT** (`worker/auth.ts:99,160,249`).
- Tapi: bertipe plain `TEXT` — **tanpa UNIQUE**, **tanpa index**, dan **semua NULL** di produksi (2 user: Bagus, Irma).
- Belum ada halaman profil maupun endpoint untuk mengubahnya.
- `/api/me` sudah mengembalikan `username` (`app/api/me/route.ts:21`) — jaring baca sudah siap.
- Input login sekarang: `<span>telegramId</span>` + `inputMode="numeric"` (`app/masuk/page.tsx:80-83`) — **memaksa angka**, jadi username huruf tidak akan bisa diketik.

**Yang harus dikerjakan:**

1. **Migrasi `0021_users_username.sql`**
   ```sql
   -- username unik, hanya huruf/angka/underscore, lowercase. Index unik parsial
   -- supaya baris NULL (belum set) tidak saling bentrok.
   CREATE UNIQUE INDEX IF NOT EXISTS idx_users_username
     ON users(lower(username)) WHERE username IS NOT NULL AND username != '';
   ```
   Index unik parsial: SQLite mendukung `WHERE` di `CREATE UNIQUE INDEX`. Ini yang mencegah dua user memakai username sama, **tanpa** memaksa semua user punya username.

2. **Aturan username** (validasi di server, bukan cuma klien):
   - 3–20 karakter, `^[a-z0-9_]+$` (lowercase)
   - Tidak boleh sama dengan tg_id user lain (cegah kebingungan saat login)
   - Tidak boleh kata terlarang (`admin`, `owner`, `root`, `telegram`) — cegah peniruan identitas
   - Disimpan lowercase; perbandingan pakai `lower(username)`

3. **Endpoint**
   - `POST /api/profil/username` — owner/admin/guest boleh ubah username sendiri
   - `GET /api/profil` — lihat username sendiri (bisa memakai `/api/me` yang sudah ada)
   - `POST /api/profil/password` — sekalian: user yang belum punya password bisa set sendiri (sekarang hanya lewat bot `/kode`)

4. **Login menerima dua bentuk** (`worker/auth.ts`):
   ```
   Masuk dengan telegramId / username + password.
   ```
   - Deteksi otomatis: input hanya angka → cari `tg_id`; ada huruf → cari `lower(username)`
   - Satu query: `WHERE (tg_id = ? OR lower(username) = ?) AND active = 1`
   - **Jangan** memberi tahu mana yang salah ("telegramId tidak ditemukan" vs "password salah") → pakai pesan seragam `"Login gagal."` (sudah jadi pola di `worker/auth.ts:108` lewat `login_audit`)

5. **UI `/masuk`**
   - Label: `telegramId atau username`
   - **Hapus `inputMode="numeric"`** (`app/masuk/page.tsx:83`) — sekarang memaksa keyboard angka, username tidak bisa diketik
   - Placeholder: `1817932703 atau bagus`
   - Pemulihan kode (`tahap === "minta-kode"`) tetap butuh telegramId — sebutkan jelas, karena kode dikirim lewat bot

6. **Halaman profil** `/profil`
   - Lihat & ubah username (dengan pratinjau ketersediaan)
   - Set/ganti password
   - Tampilkan telegramId (untuk dipakai saat minta kode)
   - Tautan ke halaman ini dari menu (ikon profil di `PageHeader`)

**Catatan keamanan:** username **bukan** pengganti password — hanya mempermudah mengingat identitas. Password tetap wajib. Rate limit login (`worker/auth.ts:108`, `login_audit`) tetap berlaku untuk kedua bentuk input, dihitung per user (bukan per teks input), supaya penyerang tidak bisa menghindari batas dengan berganti-ganti format.
