# 07 — AI (Provider, Model, Kredensial, Gambar, Analisa)

## Ringkasan area
- Dua stack AI berdampingan: (A) AKTIF `lib/ai/*.ts` — dipakai Worker + route Next, data di D1; (B) LEGACY CJS `lib/ai/{index,registry}.js`, `lib/ai/adapters/openaiCompat.js`, `lib/gemini/*` — dipakai `api/webhook.js` → `lib/router/routePesan.js`, data di Firestore, key dari `process.env`.
- Inti jalur aktif: `lib/ai/provider.ts` = orkestrator (pilih kredensial+model dari D1, rantai fallback berlapis, catat `ai_pemakaian`). Adapter per keluarga: `adapterOpenai.ts` (groq/kenari/openai/openrouter), `adapterGemini.ts` (gemini).
- Tiga bentuk panggilan: `panggilTeks` (non-stream: bot chat, vision, editor kanvas, analisa JSON), `panggilTeksStream` (SSE: `/api/analisa`), `panggilGambar` (image gen/edit: `/api/ai/gambar` + bot `@gambar`).
- Model dipilih 3 lapis: peta global `settings['ai'].modelTeks/modelVision/modelGambar` → pilihan per user (`ai_editor_setting.model_editor`, `ai_gambar_setting.model_id`) → izin per role (`ai_model_izin`), ditegakkan di `provider.ts` bukan di route.
- BUKAN area ini: guard/limit D1 umum (`lib/d1/route.ts`, lihat peta auth), rumus analisa (`lib/analisa/hitung*.ts`), skema op kanvas (`lib/desain/*`), seluruh UI dashboard (`components/dashboard/ai-*.tsx` hanya disebut sebagai pemanggil endpoint).
- `docs/ai-settings.md` USANG: mendokumenkan Firestore `/settings` (Gemini/Groq, `GEMINI_API_KEY` env), bukan jalur D1 sekarang.

## Alur data
1. Entry: `worker/bot.ts` (`jalurAiTeks`/`jalurGambar`/`jalurVision`) atau route (`app/api/ai/gambar`, `app/api/analisa`, `app/api/desain/layout`) → bangun `Konteks { db, kunci, env, role }`. `role` wajib: kosong = non-owner (fail closed).
2. `provider.ts::kandidatTeks` → `ambilPengaturanAI` (tabel `settings` key `ai`): `chainTeks` (default `["groq","gemini"]`, fallback `textProvider||"groq"`) disaring `providerSah`; `providerDiminta` dipindah/ditambahkan ke depan.
3. Per provider: `ambilKredensial` (`ai_kredensial` aktif terbaru → `dekripsi` AES-GCM dengan `AI_KEY_ENCRYPTION_KEY`) → `daftarModel(provider, jenis)` aktif urut `id` → model dipilih = `modelDiminta` (hanya provider pertama/`providerDiminta`) ?? peta `modelTeks`/`modelVision` → katalog sebagai cadangan.
4. `himpunanIzin(db, role, jenis)` (`ai_model_izin`, `owner` → `null` = tanpa batas) menyaring kandidat SEBELUM pemotongan; model `:free` digeser ke belakang; maksimal `MAKS_MODEL_PER_PROVIDER` (5) per provider.
5. `panggilTeks`/`panggilTeksStream` mengiterasi kandidat: pindah provider saat kredensial kosong, model tidak dipilih/ditolak, percobaan gagal, `ANGGARAN_PROVIDER_MS` habis, `ANGGARAN_TEKS_MS` habis, atau sisa < 3000ms. Sukses → `catatPemakaian` UPSERT `ai_pemakaian` (tanggal WIB) → hasil `{ teks, provider, model, tokenMasuk, tokenKeluar, toolCall }`.
6. Gagal semua → `gagal(502, ringkasGagal(...), catatan)` (menyebut provider tanpa kredensial / belum dicoba); kandidat kosong karena izin → `gagal(403)` lewat `gagalTanpaKandidat`.
7. Chat bot: `balasChat` → `pilihTool` (kata kunci `ai_tool_kata`) → `daftarSpesifikasiTool` → `panggilTeks` → bila `toolCall` berupa tool tulis (`ai_tool.jenis='tulis'`) TIDAK dieksekusi: balikan `perluKonfirmasi`, bot simpan `bot_sessions.pending_action_json` + tombol `ai:ya`/`ai:tidak`; `ai:ya` menjalankan `jalankanTool`.
8. Stream: potongan pertama harus tiba sebelum kandidat dikunci; setelah ada byte terkirim TIDAK ada fallback (kegagalan dilaporkan). Usage dicatat di `finally` generator.
9. Gambar: `panggilGambar` merakit rantai `chainGambar` + provider yang punya `modelGambar` + provider pilihan user; izin `jenis="gambar"`; `gambarGemini` atau `gambarOpenai` (`/images/generations`, `/images/edits` multipart).

## Endpoint & tabel terkait
- Endpoint: `POST /api/ai/gambar` → `app/api/ai/gambar/route.ts::POST` → `panggilGambar` (+`panggilTeks(...,"vision")` untuk label anotasi); guard `sesiRoute(request, 10)` + `ROLE_GAMBAR`.
- Endpoint: `GET|POST /api/ai/gambar/setting` → `aiGambarSetting`; guard sesi + `ROLE_GAMBAR`, reasoning divalidasi ke `ai_model.reasoning_pilihan`.
- Endpoint: `GET|POST /api/ai/analisa/setting` → `aiAnalisaSetting`; guard sesi, guest ditolak (bukan admin-only).
- Endpoint: `GET|POST /api/ai/editor/setting` → `aiEditorSetting`; guest ditolak; `model_editor` divalidasi ke `modelTeksBoleh` (allowlist `teks`).
- Endpoint: `GET|POST /api/pengaturan/ai` → owner only (`sesi.user.is_owner`); aksi `provider`, `pengaturan`, `kredensial-simpan|base|aktif|hapus`, `model-tambah|impor|aktif|label|hapus|kapabilitas`, `izin-simpan|hapus`, `preset-*`, `tool-*`, `tarik-model`, `pemakaian`.
- Endpoint: `POST /api/ai/gambar/kirim-telegram` → kirim hasil studio ke chat (tanpa simpan D1).
- Endpoint: `POST /api/analisa` aksi `mendalam` (JSON, `analisaMendalam`) / `mendalam-stream` & `saran-iklan-stream` (SSE, `panggilTeksStream`); `GET ?aksi=model-analisa` menampilkan rantai + kesiapan tanpa memanggil AI.
- Endpoint: `POST /api/desain/layout` → `panggilTeks` dengan `SPESIFIKASI_TOOL_EDITOR`, `modelDiminta`+`providerDiminta` dari `ai_editor_setting.model_editor`.
- Tabel D1: `ai_kredensial` (penulis `simpanKredensial`/`setAktifKredensial`, pembaca `ambilKredensial`; migrasi 0020, `base_url` 0024).
- Tabel D1: `ai_model` (penulis `tambahModel`/`tambahModelBanyak`/`perbaruiKapabilitasModel`; pembaca `daftarModel`; 0020, kolom kapabilitas 0022).
- Tabel D1: `ai_model_izin` (penulis `simpanIzin`/`hapusIzin`; pembaca `himpunanIzin`; migrasi 0035, unik `role+provider+model_id+jenis`).
- Tabel D1: `ai_gambar_setting` (0023), `ai_analisa_setting` (0031), `ai_editor_setting` (0036 + kolom `model_editor` di 0037) — satu baris per `tg_id`.
- Tabel D1: `ai_preset_prompt`, `ai_tool`, `ai_tool_kata`, `ai_pemakaian` (0020); pengaturan global di `settings` key `ai` (0001).
- Tabel D1 lain: `bot_sessions` (`history_json`, `pending_action_json`) menyimpan riwayat chat + aksi menunggu konfirmasi (lihat peta Telegram).

## Gotcha / konvensi
- Riwayat commit yang mengubah perilaku fallback: `8d3cb56` ("fallback provider akhirnya terpakai") menaikkan `ANGGARAN_PROVIDER_MS` 70000→80000 dan `ANGGARAN_TEKS_MS` 140000→240000, menambah `MIN_SISA_MS`=3000 + `batasPercobaanTeks` (kandidat pertama provider dapat jatah penuh, cadangan dipotong sisa), mengurutkan model `:free` ke belakang, dan memakai `streamGemini` di rantai stream. Aturan "potongan pertama mengunci kandidat" berasal dari `58110a3`.
- `AI_KEY_ENCRYPTION_KEY` kosong → `panggilTeks`/`panggilTeksStream`/`panggilGambar` balas 500 "AI_KEY_ENCRYPTION_KEY belum diset."; route juga memeriksa lebih dulu ("Kunci enkripsi AI belum diset."). Kunci harus base64 32 byte.
- Kunci enkripsi SALAH/berubah → `dekripsi` melempar, `ambilKredensial` mengembalikan `null`, dan gejalanya "tidak ada kredensial aktif" (bukan pesan dekripsi). Cek dulu `ai_kredensial` + secret sebelum menyalahkan provider.
- `Konteks.role` kosong/`undefined` diperlakukan non-owner → `himpunanIzin` mengembalikan himpunan kosong → 403 "Belum ada model ... diizinkan owner". Ini bukan bug kredensial.
- `modelDiminta` TANPA `providerDiminta` hanya berlaku di provider PERTAMA rantai; model di provider lain akan terabaikan (dipakai `modelTeks` provider itu).
- Fallback tidak jalan biasanya karena: `chainTeks` hanya berisi satu provider, kredensial provider berikut tidak aktif, anggaran provider habis (80s), atau jalur STREAM sudah mengirim potongan pertama (sengaja tidak fallback).
- Retry hanya untuk 429/5xx (maks 2 ulang di `panggilJson`); TIMEOUT TIDAK diulang. Stream tidak punya retry sama sekali.
- `panggilTeks` non-stream membagi waktu: kandidat pertama provider dapat jatah penuh (70s bila reasoning), cadangan dibatasi `TIMEOUT_TEKS_MS` (35s) dan sisa anggaran; `vision` selalu 60s dan tidak memakai anggaran rantai.
- Reasoning wajib dinormalisasi (`max`/`xhigh`→`high`, `none`→`minimal`); nilai mentah katalog (`max`, `xhigh`) membuat provider berpikir jauh lebih lama/400.
- `settings.rateLimitPerMenit` DISIMPAN tapi TIDAK dibaca: `worker/bot.ts` memanggil `cekBatas(..., 20)` hardcoded; route memakai `sesiRoute(request, N)` sendiri.
- `gabungTeksStatis()` (hematToken) belum dipakai siapa pun; `lib/ai/index.js`, `registry.js`, `adapters/openaiCompat.js` hanya hidup di jalur Vercel/Firestore — jangan diedit untuk memperbaiki jalur Worker.
- Izin diperiksa di `provider.ts`, bukan di route/UI: menyaring dropdown TIDAK menahan body permintaan yang dibuat tangan.
- Analisa (`/api/analisa`) memakai `hanyaModelDipilih: true` dan model diambil dari `modelTeks[provider]` GLOBAL (owner), bukan pilihan per user — `ai_analisa_setting` hanya menyimpan reasoning/token/kedalaman.
